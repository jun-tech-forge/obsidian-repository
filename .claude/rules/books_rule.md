# 書籍ノート向けカード作成ルール

## 1. 出題対象の選定

- 書籍ノートから、後から思い出す価値のある知識を優先してカード化する。
- 優先度は、次の順で判断する。
  1. 概念・用語の定義
  2. 原理・仕組み・因果関係
  3. 判断基準・条件・使い分け
  4. 重要な手順・構成要素
  5. 概念間の関係・対比
  6. 理解を補強する代表的な具体例
- 具体例や補足説明は、それ自体を覚える価値がある場合を除き、独立した問題として過剰にカード化しない。
- ノート化の時点で情報の取捨選択が行われていることを前提とし、生成件数を増やすために本文から低重要度の情報を無理に問題化しない。

---

## 2. 問題の粒度と自己完結性

- 1枚のカードでは、理解すべき1つの知識単位を扱う。
- 長い文章をそのまま暗記させず、定義・原理・条件・関係等の意味単位へ分解する。
- 問題文だけを読んで何を答えるべきか判断できるようにする。前後の章や別のカードを読んでいることを前提とする問題は原則として作成せず、必要な文脈がある場合は問題文に最小限の情報を含める。
- 複数の知識を一度に列挙させるより、それぞれを独立して問える場合は複数のBasicカードへ分割する。

---

## 3. 知識構造に応じた出題

### 3.1 列挙

- 列挙されている項目は、各項目に独立した意味や定義があるかによって扱いを分ける。
- 各項目がそれぞれ独立した概念である場合は、項目ごとにBasicカードを作成する。
- 単に上位概念の具体例として並べられており、各項目に独立した説明がない場合は、項目ごとのBasicカードを作成しない。
- 自由記述で具体例を複数挙げさせる問題や、単に項目数だけを回答させる問題等、正誤判定が曖昧または学習価値が低い問題は作成しない。

### 3.2 手順

- 手順は、順序そのものを覚える必要がある場合と、各工程の意味を理解すべき場合を区別する。
- 各工程に独立した目的・判断基準・注意点がある場合は、それぞれをBasicカードとして個別に問う。
- 順序そのものが重要な場合は、前後関係が明確になる形で出題する。ただし、多数の工程を1枚のカードですべて列挙させない。
- 単なる操作手順であり、暗記するより参照すべき性質の情報は無理にカード化しない。

### 3.3 階層関係

- 親概念の下に複数の子概念が存在する場合は、親概念と子概念の役割を分けて出題する。
- 親概念に独立した定義がある場合は、親概念の定義をBasicカードとして作成する。
- 各子概念にも独立した定義や特徴がある場合は、それぞれ個別のBasicカードを作成する。
- 複数の子概念を1枚のカードでまとめて列挙させることは原則として行わない。

### 3.4 対比・比較

- 対比・比較関係にある概念は、まず各概念を単独で理解できるカードを作成する。
- そのうえで、概念を区別するうえで重要な判断基準がある場合は、その違いを問うカードを追加してよい。
- 比較カードでは、複数の相違点を一度に列挙させず、両者を区別する主要な特徴または判断基準に絞る。

---

## 4. 重複と網羅性

- 同一の知識を問う問題を必要以上に重複して作成しない。
- 同じ内容がノート内の複数箇所で説明されている場合でも、同じ想起を要求するカードは原則として1枚に集約する。
- 一方、同じ概念でも異なる判断や利用場面を問うなど、別の角度から想起する学習価値がある場合は、複数の問題を作成してよい。
- 問題数を均等にすることではなく、重要な知識を偏りなく復習できることを網羅性の基準とする。

---

## 5. 表現と文脈

- ノートの表現は原則として尊重し、不必要な言い換えを行わない。
- ノートの言い回しが一般的な用語・表現と著しく異なり、学習上の混乱につながる場合に限り、意味を変えない範囲で一般的な表現へ置き換える。
- ノートに一般知識として整理されている内容について、書籍名や著者名を付けた「著者によれば〜」等の形式へ不要に変換しない。
- ただし、ノート自体に特定の著者・理論・立場に依存することが明示されている場合は、その文脈を失わせない。

---

## 6. コード・構文

- コードブロック全体をそのままカードへ転記せず、問いの理解に必要な最小限のコードまたは構文だけを使用する。
- import文・変数宣言・初期化処理等、問いと直接関係しない周辺コードは除外する。
- 構文の書き方を問う場合は、実際に記述する形を想起できる具体的なコード例を解答の中心とする。特定の値や変数名に依存しすぎる場合は、一般的な構造や各要素の意味を補足する。
  - 例:
    ```text
    for (let i = 0; i < 10; i++) {
      ...
    }
    ```
  - 補足: `for (初期化; 条件; 更新) { ... }` の順で記述する。
- コードの結果だけではなく、処理の目的・挙動・使い分けを理解することに価値がある場合は、それらを優先して出題する。

---

## 7. カード化しない情報

- 次の情報は原則としてカード化しない。
  - 参照位置を示すだけの章番号・節番号
  - 本文が存在しない見出し
  - 用語等に付記されたページ番号
  - 文脈を補うだけで独立した学習価値を持たない文章
  - 単なる装飾的な例や反復説明
  - 正誤判定が曖昧になる自由回答
  - 暗記するより必要時に参照することが適切な詳細情報
- 見出しのみで本文が存在しない章・節は、その箇所から推測してカードを生成しない。
